# 체육관 프로그램 노테이션 레퍼런스

우리 역도장 칠판에 적히는 프로그램 표기법의 단일 기준 문서(SSOT).
프로그램 텍스트를 파싱하거나 종목 어휘를 건드릴 때 이 문서를 먼저 읽는다.
입력 수단(붙여넣기·OCR·수기)과 무관하다. 칠판 표기법 자체만 다룬다.

---

## 0. 이 문서의 기록 규칙

**기록하는 것은 두 가지뿐이다.**

1. **실제 칠판에 적힌 원문** (2장)
2. **그 원문으로 확인된 규칙** (3~4장)

**기록하지 않는 것:**

- 추측과 추정. "이럴 것이다"는 규칙이 아니다.
- 사람이 지어낸 합성 예시. 근거가 되지 못한다.
- 코드·프롬프트에만 존재하는 규칙. 원문으로 확인되기 전까지는 구현 세부사항일 뿐이다.
- 종목 이름과 약어 목록. 진실은 DB(`base_exercises`, `gym_exercises`)에 있다.

확인되지 않은 것은 5장 「미확정」에 격리한다. **5장의 내용을 규칙으로 사용하지 않는다.**

> 이 규칙은 2026-09-02에 세웠다. 그 이전 판본에는 합성 예시와 코드 유래 추정이
> 확인된 규칙과 섞여 있었고, 그 때문에 잘못된 판단이 실제로 발생했다.

## 3. 원문으로 확인된 표기 규칙

### 3.1 프로그램 경계

- 프로그램 경계는 **빈 줄**로만 구분된다. 
- 수행 지시 외의 자연어 메모·주석은 없다.

### 3.2 곱셈 기호와 세트

- `N×M` = **N렙 × M세트**. 2026-09-11에 체육관 이용자 확인으로 확정했다.
  `back press 5x3` 은 5렙 3세트다. 뒤집어 읽는 표기는 없다.
- 곱셈 기호는 `×`(U+00D7)와 `x`가 **혼용**된다. `*`, `X`는 나타나지 않는다.
  같은 줄 안에서도 섞인다: `clean 80% 2x2, 85% 2×2, 90% 1x2`. 
- 세트 수를 생략한 표기는 없다. 모든 항목이 `xN` / `×N`으로 세트를 명시한다.

### 3.3 강도

- 강도는 전부 **% 표기**다. kg 직접 지정은 나타나지 않는다.
- **강도가 없는 항목이 있다.** 6판 모두 첫 줄 프레스 종목에 `%` 가 없다:
  `back press 5x3`(판1), `m.press 5x3`(판2), `sots press 5×3`(판3),
  `back press 5×3`(판4), `Back Press 10x3`(판5), `M Press 10x3`(판6).
  6판 6줄이 일관되므로 생략은 우연이 아니다. 강도는 선택적이다.
- 범위 표기가 존재한다: `80~90%`. → 시작 80, 끝 90.
- `%` 뒤 공백이 없는 표기가 존재한다: `70%(2+2)x2`, `75%(1+2)x1`.
- 한 줄에 강도가 여러 개면 쉼표로 나뉜 별개 항목이다:
  `hang power snatch 65% 3×2, 70% 3×2, 75% 3×2` → 세 항목.

### 3.4 종목 상속

쉼표 뒤 조각이 종목명 없이 강도로 시작하면 **앞 조각의 종목을 물려받는다.**

```text
clean 80% 2x2, 85% 2×2, 90% 1x2   → 세 항목 모두 clean
```

**상속은 줄 경계를 넘으며, 신호는 줄 끝의 쉼표다.** 판6:

```text
Squat Clean & FSQ 70% (1+2)x3,75%(1+2)x1,     ← 쉼표로 끝남
80% (1+2)x1, 85%(1+1)x3                        ← 앞 줄의 종목을 상속
```

줄바꿈 자체가 아니라 **줄 끝 쉼표**가 이어짐을 표시한다. 쉼표 없이 끝난 줄은 이어지지 않는다.
줄 단위로만 파싱하면 이 줄은 종목을 잃는다.

### 3.5 복합 동작

`&`로 이어진 별개 종목이 존재한다: `hsoc & push jerk`, `s. balance & ohs`, `Squat Clean & FSQ`.

### 3.6 복합 렙

괄호 안의 `+`는 한 세트 내부의 렙 구성이다: `(2+2)×3`, `(1+2)x3`, `(3+2)×3`, `(1+1)x3`.

**`+`는 항상 괄호 안에 온다.** 2026-09-11에 체육관 이용자 확인으로 확정했다.
판5의 `S.Balance & OHS 70% 2+1×4` 는 전사 중 괄호가 유실된 것이며 `(2+1)×4` 가 맞다.
따라서 괄호 없이 나타난 `+` 는 표기가 아니라 유실이다 — 4.2의 검출 대상이다.

### 3.7 종목 표기

- **마침표는 줄임말 표시자다.** 종목명의 일부가 아니라 "여기서 줄여 썼다"는 표시다.
  `s.` = snatch (`s.pull up` = snatch pull up, `s.balance` = snatch balance).
  → 무엇이 무엇의 줄임말인지는 **`gym_exercises`가 정한다.** 여기에 목록을 복제하지 않는다.
- **마침표 뒤에 공백을 두지 않는다**: `s.pull up`, `s.balance`, `m.press`, `S.Pull up`,
  `S.Balance`, `c.d.l`.
  예외 1건 — 판6 `C. Pull up (Pause midthigh)` 에만 공백이 있다.
- **줄임말 앞의 공백은 의미가 있다.** `low hang s.pull up` 은
  `low hang`(modifier) + `s.pull up`(종목)으로 갈린다. 공백을 무시하면 두 토큰이 붙어
  존재하지 않는 이름이 만들어진다.
- **대소문자가 혼용된다.** 같은 종목이 `back press` / `Back Press`,
  `s.balance` / `S.Balance`로 나타난다. 대소문자를 구분하면 매칭에 실패한다.
- **마침표 없는 축약도 쓰인다**: `hsoc`, `ohs` / `OHS`, `FSQ`.
- **원문 6판에 한글이 단 한 글자도 없다.** 전부 영문 표기다.

### 3.8 Modifier

칠판에서 확인된 것만 적는다. 분류 체계는 아직 근거가 없어 5장에 있다.

| 표기 | 위치 | 원문 |
| --- | --- | --- |
| `hang` | 종목명 앞 | `hang power snatch`, `hang squat clean` |
| `low hang` / `Low Hang` | 종목명 앞 | `low hang s.pull up`, `Low Hang Power Snatch` |
| `2-Pause` | 종목명 앞 | `2-Pause Snatch (under knee, Midthigh)` |
| `(Pause midthigh)` | 종목명 뒤, 괄호 | `C. Pull up (Pause midthigh)` |
| `(Pause Dip)` | 종목명 뒤, 괄호 | `Rack Jerk (Pause Dip)` |
| `(Pause Bottom)` | 종목명 뒤, 괄호 | `Front Squat (Pause Bottom)` |
| `(under knee, Midthigh)` | 종목명 뒤, 괄호 | `2-Pause Snatch (under knee, Midthigh)` |

괄호 안에 쉼표가 들어갈 수 있다(`(under knee, Midthigh)`). 쉼표를 항목 구분자로 쓸 때
괄호 안의 쉼표와 충돌한다.

### 3.9 괄호의 두 가지 용법

같은 괄호가 복합 렙(`(2+2)×3`)과 modifier(`(Pause Dip)`)에 모두 쓰인다.
원문에서 두 용법이 실재하므로 구분이 필요하다는 사실은 확인됐다.
**판정 기준 자체는 아직 확인되지 않았다 — 5장 참조.**

## 4. 오인식 패턴

OS 텍스트 인식이 칠판 글씨를 잘못 읽는 패턴. 사용자에게 표시할 대상의 SSOT다.

**원칙: 숫자가 와야 할 자리에 문자가 오면 오인식이다.**
이 표기법에서 숫자 자리에 문자가 정당하게 올 수 있는 경우는 없으므로 오탐이 발생하지 않는다.

### 4.1 관찰된 사례

| 오인식 | 실제 | 원문 근거 |
| --- | --- | --- |
| `l` ← `1` | `2xl` → `2x1`, `1xl` → `1x1` | 판5 `Back Squat 80% 4x2,85% 3x2,90% 2xl,95% 1xl` |
| `.` ← `,` | `3x2. 105%` → `3x2, 105%` | 판5 `S. Pull up 100% 3x2. 105% 3x2` |
| 괄호 유실 | `2+1×4` → `(2+1)×4` | 판5 `S.Balance & OHS 70% 2+1×4` |

`.` ← `,` 는 2026-09-02에 확정했다. 그 이전 판본은 이것을 "마침표도 구분자로 쓰인다"는
표기 규칙으로 기록했으나, 체육관에서 실제로 마침표를 쓰지 않는다는 확인에 따라
오인식으로 재분류했다. 전사본에 이미 섞여 있던 노이즈다.

3.7이 이를 뒷받침한다. **마침표는 줄임말 표시자이므로 숫자 뒤에 올 수 없다** —
숫자를 줄여 쓰는 표기가 없기 때문이다. 따라서 「숫자 뒤 마침표」는 종목명의 마침표와
구조적으로 구분되며, 오탐 없이 판정할 수 있다.

### 4.2 검출 규칙

위 원칙에서 파생되며, 이 표기법 안에서 오탐이 불가능한 범위다.

| 규칙 | 예 |
| --- | --- |
| 곱셈 기호(`x`/`×`) 뒤에 오는 `l` `I` `O` | `2xl`, `3xI` |
| `%` 바로 앞에 오는 `O` `l` `I` | `8O%`, `l00%` |
| 숫자와 숫자 사이에 낀 문자 | `1l0%` |
| 숫자 뒤 마침표 다음에 강도가 이어지는 경우 | `3x2. 105%` |
| 괄호 밖의 `+` | `2+1×4` |

마침표 규칙은 종목명의 마침표(`c.d.l`, `S. Pull up`)와 충돌하지 않는다.
판정 조건이 **숫자 뒤**이기 때문이다.

`+` 규칙은 복합 렙(`(2+2)×3`)과 충돌하지 않는다. 판정 조건이 **괄호 밖**이기 때문이다.

### 4.3 표시 원칙

- 표시만 한다. 자동으로 고치지 않는다.
- 표시가 남아 있다는 이유로 저장을 막지 않는다.
- **3장에 확인된 표기는 표시하지 않는다.** `~`, `×`/`x` 혼용, `%` 뒤 공백 없음,
  괄호 modifier, 줄을 넘는 상속은 전부 정상이다.

### 5.2 코드·프롬프트에만 존재했던 것

원문 근거가 없다. 구현 세부사항이지 표기 규칙이 아니다.

- **EBNF 문법** — 삭제된 `features/notation/model/parser.ts`(커밋 `8ef76a4^`)에서 회수한 것.
  **2장 원문을 통과시키지 못한다**: 토크나이저가 `×`(U+00D7)와 `~`를 모르고,
  `reps`에 괄호를 필수로 요구해 `2+1×4`를 거부한다. 되살리려면 원문부터 통과시켜야 한다.
- **복합 블록의 %가 두 번째 종목의 PR 기준** — 파서 주석에만 있던 규칙. 원문으로 확인 불가.
- **괄호 중의성 판정 기준** — 파서의 `isComplexRepsAhead()`가 "`( N (+N)* )` 형태이고
  바로 뒤에 `x`가 오면 복합 렙"으로 판정했다. 코드 유래.
- **접두 modifier 자동 분리 목록** — `low hang`, `hang`, `half`, `slow` 4개 하드코딩.
  이 중 `hang`과 `low hang`만 원문으로 확인됐다(3.8).
- **한글 modifier 어휘** — `무릎정지`, `발붙`, `박스 N칸`, `hold`, `slow` 등.
  Gemini 프롬프트에만 존재하며 **원문 6판에 한글이 전혀 없다.** 실제 쓰이는지 확인 필요.
- **modifier 4분류**(tempo / position / apparatus / execution) — 설계 문서 유래.
  3.8의 확인된 modifier를 이 분류가 덮는지 검증되지 않았다.
- **약어 시드** — `PS`, `HS`, `PC`, `Slow d.l`, `Snatch Dead Lift`.
  `gym_exercises` 시드에는 있으나 **칠판 6판에 한 번도 나타나지 않는다.**
  반대로 3.7에서 확인된 `hsoc`, `FSQ`, `c.d.l` 등이 시드에 있는지 확인이 필요하다.

## 7. 미해결 과제

표기법과 어휘에 관한 것만 적는다.

- **칠판 표본 부족** — 6판, 날짜 없음, 사진 원본 없음. 5장 미확정 항목 대부분이 여기서 온다.
  다음 표본을 추가할 때 날짜와 사진을 함께 남기면 해소된다.
- **어휘 이원화** — 종목 이름의 기준이 둘이다. 같은 동작이 다른 이름으로 저장되면 PR 매칭이 실패한다.
  설계: `docs/specs/2026-05-19-exercise-vocabulary-unification-design.md` (미구현)
- **확인된 축약이 시드에 있는가** — 3.7에서 확인된 `hsoc`, `ohs`, `FSQ`, `c.d.l`,
  `s.` 계열이 `gym_exercises`에 등록돼 있는지 대조되지 않았다.
  반대로 시드의 `PS`, `HS`, `PC`는 칠판 6판에 한 번도 나타나지 않는다.
