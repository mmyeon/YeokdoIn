# 프로그램 입력을 구조화 수동 입력으로 바꾼다

**Date**: 2026-11-20
**Status**: 결정됨 · 구현됨 (입력 시간 실측 전)
**대체 대상**: `specs/001-program-photo-input/spec.md` 의 결정 1(붙여넣기 단일 경로)·결정 3(텍스트 줄만 저장)

## 결정

1. **입력은 구조화 수동 입력이 기본 경로다.** 종목을 DB 목록에서 고르고, %·렙·세트를 숫자로 넣는다.
2. **앱에는 정식 종목명만 있다.** 칠판 약어(`s.pull up`, `hsoc`, `c.d.l`)는 칠판에만 남는다.
   약어 → 정식 명칭 변환은 입력하는 사람이 머릿속에서 한 번 한다.
3. **앱의 정체는 "우리 체육관 전용 도구"가 아니라 "역도 훈련 앱"이다.**
   체육관 표기법을 앱이 이해할 필요가 없다.
4. **저장 형태는 구조화 데이터다.** 기존 `Program → Block → SetEntry`
   (`features/notation/model/types.ts`)를 그대로 쓴다. 러너·`flatten.ts`·`plates.ts` 가 이미 이 형태를 읽는다.

## 근거

- **붙여넣은 프로그램은 무게를 계산하지 못한다.** `app/page.tsx` 의 `isRunnable: !isTextProgram(p)`.
  텍스트 경로는 `lines text[]` 만 저장하고 러너는 `parsed_data` 만 읽는다. 입력이 편해도 결과물이 앱의 핵심 기능에 닿지 않는다.
- **OS 텍스트 인식 결과를 믿을 수 없다.** `specs/001-program-photo-input/NEXT.md` 의 실제 아이폰 표본 2건
  (6줄, 13줄)에서 오인식 검출이 0건이었다. `15%2x3`(실제 75%)처럼 유효한 숫자로 읽힌 오류는 원리적으로 못 잡는다.
- **문제가 두 개 겹쳐 있었다.** 손글씨 인식과 약어 → 종목 매칭. `build-alias-map.ts` 는 종목명 소문자 일치만 보므로
  약어는 전부 `unresolved-alias` 로 떨어진다. 사람이 종목을 고르면 두 문제가 동시에 사라지고,
  `resolveWeight` 의 결과는 4가지에서 2가지(% 없음 / PR 없음)로 줄어든다.
- **표기 문법이 작다.** 종목 + 선택적 % + 렙×세트, 칠판 한 판이 약 7줄이다.

## 기각한 것

- **인식 품질을 올려 사진 경로를 유지한다(비전 모델 등).** 인식이 완벽해져도 약어 매칭이 남는다. 절반만 푼다.
- **약어 표기를 학습·기억한다.** 표기 기억 테이블과 부분문자열 추측기 계획이 여기에 해당한다.
  사람이 종목을 직접 고르면 필요가 없다.
- **텍스트로 저장하고 읽는 시점에 해석한다(001 결정 3).** 해석이 실패하는 줄이 생기는 순간 무게 계산이 조용히 빠진다.

## 영향

- **없앤 것**: 붙여넣기·확인 단계(`PasteStep`, `ConfirmStep`), 오인식 검출(`suspect-spans.ts`),
  텍스트 프로그램 저장·수정 경로, 이름 일치 매칭(`build-alias-map.ts`), `Movement.modifiers`.
- **남긴 것**: 러너, 플레이트 계산, `Program` 타입, `programs.lines`/`source_text` 컬럼과 그 안의 기존 행.
- **바꾼 것**: `Movement` 는 `{ exerciseId, name }` 이다. 무게 계산은 `exerciseId` 만 쓴다.
  `resolveWeight` 의 결과는 계산됨 / % 없음 / PR 없음 3가지다.
- `docs/gym-program-notation.md` 는 칠판 기록으로 남지만 코드의 기준 문서 역할은 끝났다.

## 구현하며 정한 것

- **`Movement.name` 은 저장 시점의 스냅샷이다.** 클라이언트는 종목 id 만 보내고 서버가 `exercises.name` 을 찍는다
  (`build-program.ts`). 기각: id 만 저장하고 읽을 때마다 `exercises` 를 조인한다. 목록·홈 화면까지 종목 626행을
  받아야 이름 한 줄을 그릴 수 있다. 대가는 종목 이름을 DB 에서 바꿔도 저장된 프로그램의 표시 이름은 그대로라는 것이다.
- **복합 블록의 렙은 동작마다 하나다.** 동작 2개면 `(1+1)`. 동작 하나에 `(2+1)` 을 주는 표기는 폼에서 넣을 수 없다.
- **% 는 단일 숫자다.** `93~95%` 같은 범위는 넣을 수 없다.
- **옛 텍스트 프로그램은 읽기 전용이다.** 보기와 삭제만 된다. 행을 지우거나 컬럼을 없애지 않았다.
- **복합 동작의 % 기준은 그대로 두 번째 동작이다**(`resolve-movement.ts`). 고르는 UI 는 만들지 않았다.
  실제로 틀린 무게가 나올 때 다시 연다.

## 열려 있는 것

- **입력 시간은 아직 재지 않았다.** 한 판에 60~90초라는 것은 추정이다. 실제 칠판 한 판을 폰으로 넣고 잰다.
  2분을 넘으면 「직전 항목 복제」와 「최근 종목」을 다른 무엇보다 먼저 붙인다.
  지금 있는 것은 같은 종목에 줄을 추가할 때 윗줄의 렙·세트를 물려받는 것뿐이다.
- **`programs.lines`/`source_text` 컬럼 제거.** 옛 텍스트 행을 어떻게 할지 정한 뒤에 한다.

## 재개 조건

사진 입력은 **이 폼을 미리 채워 주는 용도로만** 다시 검토한다. 저장 형태로는 돌아가지 않는다.
폼이 곧 확인 단계이므로, 폼이 먼저 있어야 사진 입력도 붙일 수 있다.
