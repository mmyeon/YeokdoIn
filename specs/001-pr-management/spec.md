# Feature Specification: 유저별 PR(개인 최고 기록) 관리

**Feature Branch**: `mmyeon/pr-list`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "유저별 PR을 등록할 수 있어야 한다. PR은 clean, snatch, back squat, front squat, deadlift, press, snatch balance로 지정한다. 무게는 kg이다. PR은 수정될 수 있다. PR은 날짜, 운동종목, 기록이 저장된다"

**Clarifications (2026-08-31)**:

 PR 등록 대상은 기존 종목 카탈로그 전체다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - PR 등록 (Priority: P1)

로그인한 사용자가 종목 카탈로그에서 종목 하나를 골라, 그 종목을 성공한 날짜와 무게(kg)를
입력해 자신의 PR로 등록한다. 등록한 PR은 목록에서 종목·무게·날짜와 함께 확인할 수 있다.

**Why this priority**: PR이 하나도 없으면 이 기능은 존재 이유가 없다. 등록만으로도
"내 최고 기록을 한 곳에서 본다"는 가치가 완성되며, 이후 모든 스토리의 전제가 된다.

**Independent Test**: PR이 하나도 없는 계정으로 로그인해 Snatch 80kg / 2026-08-20을 등록하고,
목록에 `Snatch · 80kg · 2026. 8. 20.`이 나타나는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** PR이 하나도 없는 로그인 사용자, **When** 종목 `Snatch`, 무게 `80`, 날짜 `2026-08-20`으로 등록하면, **Then** 해당 PR이 저장되고 목록에 종목·무게(kg)·날짜가 표시된다
2. **Given** 로그인 사용자, **When** 종목 선택 화면을 열면, **Then** 기존 종목 카탈로그에 등록된 종목이 선택지로 제공된다
3. **Given** 로그인 사용자, **When** 무게를 비우거나 0 이하로 입력하면, **Then** 저장되지 않고 무엇이 잘못됐는지 알려주는 메시지가 표시된다
4. **Given** 이미 `Snatch` PR이 있는 사용자, **When** 같은 종목을 다시 등록하려 하면, **Then** 중복 생성 대신 기존 기록을 갱신하는 흐름으로 안내된다
5. **Given** 비로그인 사용자, **When** PR 화면에 접근하면, **Then** 인증이 요구되고 타인의 PR은 조회되지 않는다

---

### User Story 2 - PR 수정 (Priority: P1)

기록을 잘못 입력했거나 새 기록을 세운 사용자가 기존 PR의 무게와 날짜를 수정한다.

**Why this priority**: PR은 본질적으로 갱신되는 값이다. 수정이 없으면 사용자는 틀린 값을
안고 살거나 기능을 버린다. 등록과 함께 P1을 이룬다.

**Independent Test**: 이미 `Back Squat 120kg`이 등록된 계정에서 `130kg / 2026-08-25`로 수정한 뒤
목록과 상세에 새 값이 반영되는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** `Back Squat 120kg / 2026-07-01` PR을 가진 사용자, **When** 무게를 `130`, 날짜를 `2026-08-25`로 수정하면, **Then** 목록과 상세에 새 값이 반영되고 이전 값은 더 이상 현재 PR로 표시되지 않는다
2. **Given** 기존 PR, **When** 무게를 0 이하 또는 비어 있는 값으로 수정하면, **Then** 저장이 거부되고 기존 값이 유지된다
3. **Given** 기존 PR, **When** 미래 날짜를 입력하면, **Then** 저장이 거부되고 사유가 안내된다
4. **Given** 기존 PR, **When** 수정 중 저장에 실패하면, **Then** 사용자에게 실패가 명확히 알려지고 기존 값이 손상되지 않는다

---

### User Story 3 - PR 목록 조회 (Priority: P2)

사용자가 자신의 PR을 한 화면에서 훑어보고, 아직 등록하지 않은 종목이 무엇인지 파악한다.

**Why this priority**: 등록·수정이 있으면 값은 존재하지만, 한눈에 보는 뷰가 있어야 훈련 중
참조라는 실사용 가치가 생긴다. 등록/수정 없이는 성립하지 않으므로 P2.

**Independent Test**: 3개 종목만 등록된 계정으로 목록을 열어, 등록된 3개가 값과 날짜와 함께
표시되고 미등록 종목과 구분되는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** 3개 종목 PR을 가진 사용자, **When** PR 목록을 열면, **Then** 등록된 종목은 무게·날짜와 함께 표시되고 미등록 종목과 구분된다
2. **Given** PR이 하나도 없는 사용자, **When** 목록을 열면, **Then** 빈 상태 안내와 첫 등록으로 이어지는 경로가 제공된다

---

### User Story 4 - 종목별 과거 기록·추이 조회 (Priority: P3)

사용자가 PR 목록에서 종목 하나를 선택하면, 그 종목의 과거 기록들과 무게가 어떻게 변해왔는지
추이를 확인한다.

**Why this priority**: 등록·수정(P1)으로 값이 쌓이고 목록(P2)으로 현재 상태를 본 다음에야
"내가 늘고 있는가"라는 질문이 성립한다. 앞 스토리 없이는 볼 데이터 자체가 없으므로 P3다.
다만 역도 훈련에서 진전 확인은 PR을 기록하는 근본 동기이므로 P3 중 최우선이다.

**Independent Test**: `Back Squat`에 서로 다른 날짜의 기록이 3건 쌓인 계정에서 해당 종목을
선택해, 3건이 날짜순으로 보이고 추이가 함께 표시되는지 확인하면 단독 검증된다.

**Acceptance Scenarios**:

1. **Given** `Back Squat`에 여러 건의 과거 기록이 쌓인 사용자, **When** PR 목록에서 `Back Squat`을 선택하면, **Then** 해당 종목의 과거 기록이 날짜순으로 표시된다
2. **Given** 같은 사용자, **When** 종목 상세를 열면, **Then** 기록의 변화 추이를 시각적으로 파악할 수 있다
3. **Given** 과거 기록이 1건뿐인 종목, **When** 상세를 열면, **Then** 추이 대신 현재 기록만 표시되고 오류 없이 동작한다
4. **Given** 사용자가 PR을 수정, **When** 종목 상세를 다시 열면, **Then** 수정 결과가 과거 기록에 반영되어 보인다
5. **Given** 타 사용자의 기록 식별자로 상세에 접근, **When** 조회를 시도하면, **Then** 거부된다

---

### Edge Cases

- 같은 종목에 대해 두 번째 PR을 등록하려 할 때 → 새 행이 생기지 않고 기존 기록 갱신으로 수렴한다
- 새로 입력한 무게가 기존 PR보다 낮을 때 → 오기 수정일 수 있으므로 차단하지 않고 저장하되, 값이 내려간다는 사실을 사용자에게 알린다
- 미래 날짜 입력 → 거부
- 소수점 무게(예: 62.5kg) → 허용 안함. 1kg가 최소 단위. 
- 비정상적으로 큰 무게(예: 1000kg 초과) → 오입력으로 보고 거부
- 네트워크 실패로 저장이 끊긴 경우 → 부분 저장 없이 실패로 처리하고 재시도 가능
- 타 사용자의 PR 식별자를 직접 지정한 수정/조회 시도 → 거부
- 과거 기록이 0~1건이라 추이를 그릴 수 없는 종목 → 빈 추이가 아니라 현재 기록만 표시
- 같은 날짜에 기록이 여러 건 존재 → 오류 없이 모두 표시
- 카탈로그에 없는 종목명(예: military press)으로 PR을 남기고 싶은 경우 → 이번 범위에서는 지원하지 않는다. 카탈로그의 가장 가까운 종목을 선택한다

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 인증된 사용자별로 PR을 저장하고, 각 사용자는 자신의 PR만 조회·수정할 수 있어야 한다
- **FR-002**: 시스템은 기존 종목 카탈로그에 등록된 종목을 PR 대상으로 제공해야 한다. 이 기능은 종목을 추가·삭제·개명하지 않는다
- **FR-003**: 사용자는 종목·무게·날짜를 입력해 PR을 등록할 수 있어야 한다
- **FR-004**: 시스템은 PR 1건당 운동 종목, 무게, 달성 날짜를 저장해야 한다
- **FR-005**: 시스템은 무게를 kg 단위로 저장·표시해야 하며, 다른 단위를 제공하지 않는다
- **FR-006**: 시스템은 (사용자, 종목) 조합당 현재 PR을 최대 1건만 유지해야 한다
- **FR-007**: 사용자는 기존 PR의 무게와 날짜를 수정할 수 있어야 한다
- **FR-008**: 시스템은 0 이하이거나 비어 있는 무게 입력을 거부하고 사용자에게 사유를 알려야 한다
- **FR-009**: 시스템은 미래 날짜의 달성 날짜를 거부해야 한다
- **FR-010**: 시스템은 1kg 단위까지 허용해야 한다
- **FR-011**: 시스템은 저장 실패 시 기존 값을 변경하지 않고 실패를 사용자에게 알려야 한다
- **FR-012**: 사용자는 자신의 PR 전체를 한 목록에서 조회할 수 있어야 하며, 미등록 종목은 등록된 종목과 구분되어야 한다
- **FR-013**: 시스템은 이미 등록된 기존 PR을 이 기능 도입으로 인해 삭제하거나 감추지 않아야 한다
- **FR-014**: 사용자는 PR 목록에서 종목을 선택해 그 종목의 과거 기록을 조회할 수 있어야 한다
- **FR-015**: 시스템은 종목별 과거 기록을 날짜순으로 표시하고, 각 기록의 무게와 날짜를 보여야 한다
- **FR-016**: 시스템은 종목별 기록의 변화 추이를 시각적으로 제공해야 한다
- **FR-017**: 시스템은 과거 기록이 추이를 그리기에 부족한 경우(0~1건)에도 오류 없이 현재 상태를 표시해야 한다
- **FR-018**: 시스템은 과거 기록 조회에도 소유자 검증을 적용해, 사용자가 자신의 기록만 볼 수 있게 해야 한다

### Key Entities *(include if feature involves data)*

- **User**: PR의 소유자. 인증된 사용자 1명이 자신의 PR 집합을 갖는다
- **Exercise (종목)**: PR을 등록할 수 있는 종목. 기존 종목 카탈로그가 유일한 진실의 출처이며, 이 기능은 카탈로그를 읽기만 한다
- **Personal Record (PR)**: 사용자 1명 + 종목 1개에 대한 현재 최고 기록. 속성은 무게(kg), 달성 날짜이며, 마지막 수정 시각을 함께 보관한다. (사용자, 종목)당 1건
- **PR History Entry (과거 기록)**: 특정 사용자·종목의 시점별 기록 1건. 속성은 무게, 날짜, 이전 무게, 메모, 기록 출처. 한 종목에 여러 건이 쌓이며 추이의 재료가 된다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 PR 화면 진입부터 첫 PR 등록 완료까지 30초 이내에 도달할 수 있다
- **SC-002**: 사용자는 기존 PR 수정을 3번 이하의 조작(선택 → 값 변경 → 저장)으로 완료할 수 있다
- **SC-003**: 잘못된 입력(0 이하 무게, 미래 날짜)은 100% 저장 전에 차단되고, 사용자는 무엇이 잘못됐는지 알 수 있다
- **SC-004**: 사용자는 자신이 등록한 PR 전체를 목록 한 곳에서 확인할 수 있으며, 원하는 종목을 찾는 데 5초를 넘기지 않는다
- **SC-005**: 어떤 사용자도 다른 사용자의 PR을 조회하거나 수정할 수 없다 (권한 테스트 100% 통과)
- **SC-006**: PR 등록·수정 후 목록에 반영되기까지 사용자가 기다린다고 느끼지 않는다 (체감 지연 없음)
- **SC-007**: 사용자는 PR 목록에서 한 번의 선택으로 해당 종목의 과거 기록과 추이에 도달할 수 있다
- **SC-008**: 사용자는 종목 상세를 열고 5초 이내에 자신의 기록이 늘고 있는지 줄고 있는지 판단할 수 있다

## Assumptions

- 인증은 기존 시스템을 그대로 사용한다. 이 기능은 인증 방식을 새로 정의하지 않는다
- 종목 카탈로그는 이 기능의 범위 밖이다. 종목의 추가·개명·정리는 별도 작업으로 다룬다
- 무게 단위는 kg 고정이며 lb 변환·단위 설정은 범위 밖이다
- PR은 수동 입력으로만 등록·수정된다. 훈련 일지나 프로그램 실행 결과로부터의 자동 감지는 이 명세의 범위 밖이다.
- "기록"은 무게 1개 값을 뜻한다. 반복 수(예: 3RM)나 세트 정보는 저장하지 않으며, PR은 1RM 성격의 단일 최고 무게로 해석한다
- 종목별 과거 기록은 **조회**까지를 이번 범위로 정한다. 과거 기록 항목을 사용자가 직접 추가·수정·삭제하는 동작은 이번 명세에서 정하지 않으며, 현재 구현을 그대로 둔다. 필요해지면 별도 명세로 다룬다
- 과거 기록은 PR 등록·수정의 결과로 쌓이는 것을 기본 경로로 본다. 훈련 결과로부터의 자동 감지는 범위 밖이다
- 새 값이 기존 PR보다 낮아도 저장을 허용한다. 오기 정정인 경우 오기를 삭제해서 히스토리에 남지 않게 한다. 
- 이 기능은 기존 `설정 > Personal Records` 화면과 그 데이터를 이어받아 정리하는 것을 전제로 한다. 신규 저장소를 병렬로 만들지 않는다
