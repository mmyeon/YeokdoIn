# 검증 가이드: PR 기록 낙관적 반영

## 준비

```bash
npx supabase start   # Docker Desktop 먼저
npm run dev
```

로그인 → 설정 → PR → 기록이 2건 이상인 종목의 상세 화면.

## 자동 검증

```bash
npx jest features/personal-records hooks/__tests__
npx tsc --noEmit
npm run build        # dev 서버를 끈 뒤 (.next 공유 충돌)
```

- `model/__tests__/` — 정렬 위치, 현재 PR 계산(최대 삭제·동점·0건), 역연산이 원상복구되는지.
- 낙관적 훅 테스트 — `mutationFn` 을 지연·실패 목으로 바꿔:
  - 응답 전에 두 캐시가 이미 바뀌어 있다.
  - 실패하면 두 캐시가 직전 값으로 돌아오고 `onError` 가 입력값(variables)을 받는다.
  - **삭제 A·B를 연달아, A만 실패** → B는 지워진 채 남는다 (spec 경계 "연속 조작").
  - 조작이 겹치면 마지막 조작이 끝날 때만 재조회한다.
  - 오프라인(`onlineManager.setOnline(false)`)에서 멈추지 않고 실패한다(기존 오프라인 테스트 이관).

## 수동 검증 (spec "검증" 절)

| # | 방법 | 기대 |
|---|---|---|
| 1 | DevTools Network → 느린 속도(Slow 3G 등)로 추가·수정·삭제 | 누르는 즉시 목록·현재 PR·그래프가 모두 바뀜. 성공 토스트 없음 |
| 2 | 현재 PR(최대 무게) 기록 삭제 | 헤더가 즉시 다음으로 큰 무게로 |
| 3 | 과거 날짜로 기록 추가 | 맨 위가 아니라 날짜 순 자리에 바로 들어가고, 응답 후 점프 없음 |
| 4 | DevTools Offline 후 추가 | 잠깐 반영 → 되돌아감 → 실패 토스트 → 폼이 입력값째 다시 열림 |
| 5 | Offline 후 수정 | 위와 같고, 수정 폼이 수정하려던 값으로 다시 열림 |
| 6 | Offline 후 삭제 | 행이 되돌아오고 실패 토스트. 버튼이 '저장중'에 멈추지 않음 |
| 7 | 방금 추가한 행(응답 전) | 메뉴가 비활성 |
| 8 | 목록 화면에서 미등록 종목 PR 등록 | **변화 없음** — 저장 후 닫히고 성공 토스트(FR-006) |

연속 삭제 중 하나만 실패하는 경우는 수동으로 재현하기 어려워 훅 테스트로만 검증한다.
