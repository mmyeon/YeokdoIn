# Quickstart: 화이트보드 프로그램 입력 검증

구현 완료 후 이 문서대로 실행해 기능을 검증한다.

## 사전 조건

- Docker Desktop 실행 중
- `npx supabase start` → `npm run dev`
- 로그인된 계정 1개

## 자동 검증

```bash
npm run test        # jest + 커버리지 (features/programs/model 임계 80%)
npm run type-check  # tsc --noEmit
npm run build
```

세 개 모두 통과해야 커밋할 수 있다(헌법 Quality Gates).

### 골든 케이스 — SC-005

`docs/gym-program-notation.md` 2장의 칠판 원문 6판(40줄)을 `findSuspectSpans`에 전량 입력하는
테스트가 있어야 한다. 기대: 4.1의 4건(`2xl`, `1xl`, `3x2. 105%`, `2+1`) 외 검출 0건.
계약은 [contracts/model.md](./contracts/model.md) 참조.

## 수동 검증

`/training/program-input`에서 수행한다.

### 1. 등록 (US1)

문서 2장의 판1을 클립보드에 넣고 붙여넣는다.

- [ ] 붙여넣은 텍스트가 그대로 보이고, 불릿 목록은 **나타나지 않는다** (FR-002)
- [ ] 「다음」을 누르면 대기 없이 즉시 7개 불릿이 나타난다 (SC-002)
- [ ] 빈 줄이 항목이 되지 않고, 앞뒤 공백이 제거돼 있다 (FR-007, FR-008)
- [ ] `×`, `~`, `%`가 원문 그대로 보존돼 있다 (FR-011)
- [ ] 저장 후 목록에서 같은 내용을 다시 볼 수 있다

### 2. 빈 입력

- [ ] 입력이 비었거나 공백뿐일 때 「다음」이 진행되지 않고 안내가 뜬다 (FR-004)
- [ ] 확인 단계에서 항목을 전부 삭제하면 저장이 거부된다 (FR-032)

### 3. 의심 구간과 수정 (US2)

`Back Squat 80% 4x2,85% 3x2,90% 2xl,95% 1xl` 를 붙여넣는다.

- [ ] `2xl`, `1xl`이 시각적으로 구분된다 (FR-012)
- [ ] `80%`, `4x2` 같은 정상 표기는 표시되지 않는다 (SC-005)
- [ ] 아무것도 고치지 않고 저장해도 막히지 않는다 (FR-014)
- [ ] `2xl`을 `2x1`로 고치면 표시가 즉시 사라진다 (FR-016)
- [ ] 항목 추가·삭제·병합·분할이 순서대로 반영된다 (FR-019)
- [ ] 한 항목 수정이 다른 항목에 영향을 주지 않는다 (FR-017)
- [ ] 편집 중 브라우저 맞춤법 밑줄이 뜨지 않는다 (FR-015)

문서 3장의 정상 표기가 표시되지 않는지 판1의 `80~90%`, 판6의 `70%(1+2)x1`로 확인한다.

### 4. 이탈과 실패

- [ ] 확인 단계에서 입력 단계로 돌아가는 경로가 **없다** (FR-006)
- [ ] 확인 단계를 벗어나려 하면 폐기 경고가 뜬다 (FR-006)
- [ ] 네트워크를 끊고 저장하면 실패를 알리되 편집 내용이 남고 재시도된다 (FR-036, SC-008)

### 5. 재조회와 삭제 (US3)

- [ ] 목록에 자신의 프로그램만 최신순으로 보인다 (FR-034)
- [ ] 저장본을 열어 항목을 고치면 새 행이 생기지 않고 갱신된다 (FR-021)
- [ ] 삭제하면 목록에서 사라진다 (FR-035)

### 6. 레거시 회귀

기존 폼으로 저장해 둔 프로그램이 있을 때:

- [ ] 목록에 정상 표시된다
- [ ] 러너 진입이 여전히 동작한다
- [ ] 텍스트 프로그램 카드에는 러너 진입이 노출되지 않는다 (research.md R4)
- [ ] 종목 필터(Snatch/C&J/Squat)에 두 형태가 모두 걸린다

### 7. 분량

- [ ] 20줄 이상을 붙여넣어도 「다음」이 1초 이내다 (SC-003)
- [ ] 불릿 목록에서 스크롤과 편집이 끊기지 않는다

## DB 확인

```bash
psql postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  -c "select id, title, array_length(lines,1) as n, parsed_data is null as is_text from programs order by created_at desc limit 5;"
```

- [ ] 새 행은 `is_text = t`, `n`이 화면의 항목 수와 일치한다 (SC-004)
- [ ] `source_text`에 편집 이전 원문이 남아 있다 (FR-031)
- [ ] 레거시 행의 `parsed_data`가 그대로다

스키마 변경 후에는 `npm run generate-types`를 실행하고 산출물을 같은 커밋에 포함한다(헌법 II).
