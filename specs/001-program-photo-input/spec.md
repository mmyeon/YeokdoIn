# Feature Specification: 화이트보드 프로그램 입력

**Feature Branch**: `mmyeon/program-input`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "화이트보드에 쓰여진 프로그램을 사진 찍어 앱에 프로그램 데이터로 저장. (1) OCR로 이미지 분석 (2) 기본 카메라앱의 텍스트 복사 활용. 성능이 가장 중요. 프로그램은 보통 8줄 이상. 오타는 유저가 수정 가능해야 함. 결과물은 불릿 형태로 표시. 다룰 것: 입력 방식 / 수정 / 표시 / DB 저장"

**결정 사항** (2026-09-02 확정):

1. **입력 경로** — 텍스트 붙여넣기 단일 경로. OS 기본 카메라의 텍스트 인식으로 복사한 뒤 앱에 붙여넣는다.
   앱 내 이미지 인식(OCR)은 이번 범위에서 제외한다.
2. **입력 흐름** — 붙여넣기와 확인을 2단계로 나눈다. 붙여넣는 즉시 불릿을 그리지 않고,
   사용자가 「다음」을 눌렀을 때 불릿 목록으로 넘어간다.
3. **저장 단위** — 사용자가 확정한 텍스트 줄만 저장한다. 종목·강도·렙·세트로의 구조화는 하지 않는다.
   구조가 필요한 화면(러너, PR 환산)이 생길 때 읽는 시점에 해석한다.
4. **정제의 의미** — 절차적 정제. 사용자가 눈으로 확인하고 확정한 것만 저장하며,
   앱은 내용의 표기 규약 적합성을 판정하지 않는다. 위생 처리(공백·빈 줄·제어문자)만 수행한다.
5. **의심 구간 표시** — 숫자가 와야 할 자리에 문자가 인식된 경우만 표시한다.
   표기 규약 전반의 적합성 검사는 하지 않는다(근거는 FR-013).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 텍스트를 붙여넣어 프로그램을 등록한다 (Priority: P1)

훈련자가 체육관에 도착해 칠판을 본다. 휴대폰 기본 카메라를 칠판에 비추면 OS가 글자를 인식해 주고,
그 텍스트를 통째로 복사한다. 앱의 입력 화면에 붙여넣고 「다음」을 누르면,
프로그램이 한 줄씩 불릿으로 정리돼 나타난다. 훈련자는 눈으로 훑고 저장한다.

**Why this priority**: 이 기능의 전부다. 서버 왕복도, 이미지 업로드도, 인식 대기도 없어 가장 빠르다.
훈련 시작 직전에 끝나야 하는 작업이므로 체감 속도가 성패를 가른다.

**Independent Test**: 실제 칠판 원문(`docs/gym-program-notation.md` 2장의 6판)을 클립보드에
넣고 붙여넣기 → 「다음」 → 불릿 표시 → 저장까지 수행해 단독 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 8줄 이상의 프로그램 텍스트가 클립보드에 있고 입력 화면이 열려 있을 때,
   **When** 사용자가 텍스트를 붙여넣으면,
   **Then** 입력한 텍스트가 그대로 보이고 「다음」으로 진행할 수 있게 되며, 불릿 목록은 아직 나타나지 않는다.
2. **Given** 텍스트를 붙여넣은 상태에서,
   **When** 사용자가 「다음」을 누르면,
   **Then** 앱은 대기 표시 없이 즉시 각 줄을 항목 불릿으로 나눈 확인 화면을 보여 준다.
3. **Given** 붙여넣은 텍스트에 빈 줄이나 줄 앞뒤 공백이 섞여 있을 때,
   **When** 앱이 항목을 나누면,
   **Then** 빈 줄은 항목으로 만들지 않고, 각 항목의 앞뒤 공백은 제거된다.
4. **Given** 확인 화면에서,
   **When** 사용자가 저장을 누르면,
   **Then** 프로그램이 저장되고 저장된 내용을 다시 열어 동일하게 볼 수 있다.
5. **Given** 입력이 비어 있거나 공백뿐일 때,
   **When** 사용자가 「다음」을 시도하면,
   **Then** 앱은 진행하지 않고 입력이 필요함을 알린다.
6. **Given** 붙여넣은 텍스트에 `×`, `~`, `%`, 마침표 구분자 등 칠판 표기 문자가 섞여 있을 때,
   **When** 앱이 항목을 나누면,
   **Then** 어떤 문자에서도 처리가 중단되지 않고 원문 그대로 항목에 보존된다.

---

### User Story 2 - 인식된 내용의 오타를 고친다 (Priority: P1)

칠판 글씨는 흘려 쓰였고 OS 텍스트 인식 결과에는 늘 오류가 섞인다. 숫자 `1`이 글자 `l`로 읽히고,
한 줄이 둘로 쪼개지기도 한다. 앱은 숫자 자리에 문자가 들어온 곳을 표시해 주고,
훈련자는 표시된 곳과 눈에 걸리는 곳을 그 자리에서 눌러 고친다.

**Why this priority**: 인식 정확도를 100%로 만들 수 없다는 것이 전제이므로, 수정 없이는
US1의 저장 결과를 신뢰할 수 없다. US1과 함께 있어야 기능이 완결된다.

**Independent Test**: 의도적으로 오타를 심은 텍스트(`Back Squat 80% 4x2,85% 3x2,90% 2xl,95% 1xl`)를
붙여넣고, 표시가 뜨는지 확인한 뒤 수정·추가·삭제·병합·분할을 거쳐 저장해 수정본이 남는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 항목에 `2xl`처럼 숫자 자리에 문자가 인식된 부분이 있을 때,
   **When** 확인 화면이 표시되면,
   **Then** 해당 구간이 시각적으로 구분돼 사용자의 주의를 끈다.
2. **Given** 의심 구간이 표시된 항목에서,
   **When** 사용자가 아무 조치도 하지 않고 저장하면,
   **Then** 앱은 저장을 막지 않고 표시된 내용 그대로 저장한다.
3. **Given** 확인 화면에서,
   **When** 사용자가 특정 항목을 선택하면,
   **Then** 그 항목의 텍스트를 편집할 수 있는 상태가 되고 나머지 항목은 그대로 유지된다.
4. **Given** 한 항목을 수정한 뒤,
   **When** 편집을 마치면,
   **Then** 수정된 내용이 즉시 불릿에 반영되고 다른 항목은 영향을 받지 않으며, 의심 구간 표시가 다시 계산된다.
5. **Given** 인식이 한 줄을 두 줄로 쪼갰거나 두 줄을 한 줄로 붙였을 때,
   **When** 사용자가 항목을 추가·삭제·병합·분할하면,
   **Then** 항목 수와 순서가 사용자의 편집대로 반영된다.
6. **Given** 모든 항목을 삭제했을 때,
   **When** 사용자가 저장을 시도하면,
   **Then** 앱은 빈 프로그램을 저장하지 않고 이를 알린다.

---

### User Story 3 - 저장한 프로그램을 다시 보고 고친다 (Priority: P2)

훈련자가 나중에 저장한 프로그램을 열어 확인하고, 잘못 저장한 항목을 고치거나
필요 없어진 프로그램을 지운다.

**Why this priority**: 등록만 되고 다시 볼 수 없으면 저장의 의미가 없다. 다만 US1·US2가
동작하면 최소한의 가치는 이미 전달되므로 P2다.

**Independent Test**: 저장된 프로그램을 목록에서 찾아 열고, 항목을 수정해 갱신하고,
삭제까지 수행해 단독 검증한다.

**Acceptance Scenarios**:

1. **Given** 프로그램을 여러 개 저장한 사용자가,
   **When** 프로그램 목록을 열면,
   **Then** 자신의 프로그램만 최신순으로 보인다.
2. **Given** 저장된 프로그램을 열었을 때,
   **When** 사용자가 항목을 수정하고 다시 저장하면,
   **Then** 새 프로그램이 만들어지지 않고 기존 프로그램이 갱신된다.
3. **Given** 저장된 프로그램을 열었을 때,
   **When** 사용자가 삭제를 확인하면,
   **Then** 해당 프로그램이 목록에서 사라지고 다시 조회되지 않는다.

---

### Edge Cases

- 프로그램이 8줄을 크게 넘어 20줄 이상일 때도 스크롤·편집이 끊기지 않아야 한다.
- 한 항목이 다음 줄로 이어지는 경우(`Squat Clean & FSQ 70% (1+2)x3,75%(1+2)x1` 다음 줄이 `80% (1+2)x1`)
  줄 단위로 잘라도 사용자가 병합해 바로잡을 수 있어야 한다.
- 한 줄에 두 종목이 구분자 없이 붙어 있는 경우 사용자가 항목을 나눌 수 있어야 한다.
- `×`(U+00D7)와 `x`, `~`(범위), `%` 뒤 공백 없는 표기, 마침표 구분자 등 칠판에 실재하는 문자가
  입력돼도 처리가 중단되지 않아야 하며, 의심 구간으로도 표시되지 않아야 한다.
- 붙여넣은 텍스트의 줄바꿈이 `\n`이 아닌 다른 형태(`\r\n`)여도 항목 분해가 동일해야 한다.
- 확인 화면에서 뒤로 가거나 화면을 벗어나려 할 때 편집 중인 내용이 소실됨을 알려야 한다.
- 저장 요청이 네트워크 문제로 실패하면 편집 중인 항목이 사라지지 않고 재시도할 수 있어야 한다.
- 같은 칠판을 두 번 등록했을 때 중복 저장을 막지는 않되 사용자가 구분할 수 있어야 한다.
- 항목을 편집해 의심 구간이 사라지거나 새로 생기면 표시가 즉시 따라가야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**입력 (2단계)**

- **FR-001**: 시스템은 사용자가 프로그램 텍스트를 붙여넣거나 직접 입력하는 입력 단계와,
  분해된 항목을 확인·수정하는 확인 단계를 분리해 제공해야 한다.
- **FR-002**: 입력 단계에서는 항목 분해 결과를 표시하지 않아야 한다. 사용자가 명시적으로
  다음 단계로 진행할 때만 분해가 화면에 반영된다.
- **FR-003**: 입력 단계에서 다음 단계로의 진행에는 서버 왕복이 없어야 한다.
- **FR-004**: 입력이 비어 있거나 공백뿐이면 시스템은 다음 단계로의 진행을 막고 사용자에게 알려야 한다.
- **FR-005**: 시스템은 앱 내부에서 이미지를 촬영하거나 분석하지 않는다. 텍스트 인식은 사용자의 OS 기본 기능에 위임한다.
- **FR-006**: 확인 단계에서 입력 단계로 되돌아가는 경로는 제공하지 않는다. 확인 단계를 벗어나는
  것은 등록 폐기로 취급하며, 폐기 전 사용자에게 알려야 한다.

**항목 분해**

- **FR-007**: 시스템은 입력된 텍스트를 줄 단위 항목 목록으로 분해해야 하며, 빈 줄과 공백뿐인 줄은 항목으로 만들지 않아야 한다.
- **FR-008**: 시스템은 각 항목의 앞뒤 공백을 제거하되, 항목 내부의 문자는 원문 그대로 보존해야 한다.
- **FR-009**: 시스템은 항목의 원래 순서를 보존해야 한다.
- **FR-010**: 시스템은 줄바꿈 표현 방식과 무관하게 동일한 분해 결과를 내야 한다.
- **FR-011**: **분해 단계에서는** 어떤 문자가 들어와도 처리를 중단하거나 내용을 버리지 않아야 한다.
  표기 규약에 맞지 않는 내용도 사용자가 확인·수정할 수 있도록 항목으로 제시된다.
  이 조항은 분해 단계에만 적용되며, 저장 대상을 규정하지 않는다(FR-024 참조).

**의심 구간 표시**

- **FR-012**: 시스템은 오인식으로 판정되는 구간을 확인 단계에서 시각적으로 표시해야 한다.
  검출 대상의 단일 출처는 `docs/gym-program-notation.md` 4장이며, 명세는 목록을 복제하지 않는다.
  현재 확정된 원칙은 「숫자가 와야 할 자리에 문자가 오면 오인식」이다.
- **FR-013**: 시스템은 표기 규약 전반의 적합성은 검사하지 않으며, 규약에 어긋난다는 이유로
  구간을 표시하지 않는다.
  *근거*: `docs/gym-program-notation.md` 5.2에 따르면 현행 EBNF 문법은 코드 유래이며
  2장 원문을 통과시키지 못한다(`×`, `~` 미인식, 괄호 없는 복합 렙 거부). 미확정 문법으로
  검사하면 3장의 정상 표기에 오탐이 발생해 표시 자체가 무의미해진다.
- **FR-014**: 의심 구간 표시는 알림에 그쳐야 한다. 시스템은 내용을 자동으로 수정하지 않으며,
  표시가 남아 있다는 이유로 저장을 막지 않는다.
- **FR-015**: 시스템은 플랫폼 기본 맞춤법 검사를 입력·편집 영역에서 비활성화해야 한다.
  일반 언어 사전은 종목명과 표기 기호를 전부 오류로 판정해 의심 구간 표시를 가린다.
- **FR-016**: 사용자가 항목을 편집하면 의심 구간 표시는 즉시 재계산돼야 한다.

**수정**

- **FR-017**: 사용자는 각 항목의 텍스트를 개별적으로 수정할 수 있어야 하며, 한 항목의 수정이 다른 항목에 영향을 주지 않아야 한다.
- **FR-018**: 사용자는 항목을 추가·삭제할 수 있어야 한다.
- **FR-019**: 사용자는 잘못 나뉜 항목을 병합하거나 한 항목을 둘로 나눌 수 있어야 한다.
- **FR-020**: 시스템은 저장 전 편집 상태를 유지해, 저장 실패로 사용자의 수정이 소실되지 않게 해야 한다.
- **FR-021**: 사용자는 저장된 프로그램을 다시 열어 항목을 수정하고 갱신할 수 있어야 한다.

**표시**

- **FR-022**: 시스템은 프로그램을 항목당 하나의 불릿으로 하는 목록 형태로 표시해야 한다.
- **FR-023**: 불릿 목록은 8줄 이상의 프로그램에서 최소한의 스크롤로 전체 윤곽을 파악할 수
  있도록 항목당 표시 높이를 절제해야 한다. 다만 한 항목에 강도가 둘 이상이면 줄을 나눌 수
  있다(FR-026a) — 한 줄에 몰아넣은 표시가 읽히지 않는다는 것이 실사용에서 확인됐고,
  줄을 나눈 편이 전체 윤곽 파악에 더 낫다고 판단했다.
- **FR-024**: 목록의 모든 항목은 편집 가능해야 하며, 항목을 눌러 바로 수정에 진입할 수 있음이 화면에서 드러나야 한다.
- **FR-025**: 시스템은 사용자가 저장 전에 전체 항목 수를 확인할 수 있게 해야 한다.
- **FR-026**: 시스템은 항목 텍스트의 **문자를 바꾸거나 버리지 않고** 사용자가 확정한 그대로
  표시해야 한다. 문자를 보태거나, 빼거나, 다른 문자로 바꾸지 않는다.
- **FR-026a**: 시스템은 읽기를 돕기 위해 항목의 **배치와 강조**를 바꿀 수 있다. 강도 강조,
  쉼표 자리의 줄바꿈, 강도가 둘 이상인 항목을 종목명 줄과 강도 줄로 나누어 그리는 것이
  여기에 속한다. 배치를 나누는 기준은 **괄호 밖의 쉼표**다 — 괄호 안의 쉼표는 구분자가
  아니다(`docs/gym-program-notation.md` 3.8).
  이 배치는 표시에만 존재한다. 저장 형태는 여전히 항목당 텍스트 한 줄이며(FR-029),
  값으로 해석하지 않는다.
- **FR-026b**: 편집 중에도 같은 배치가 보여야 한다. 편집 버퍼는 괄호 밖 쉼표를 줄바꿈으로
  바꾸어 보여주고, 확정 시 줄바꿈을 쉼표로 되돌린다. 문자 하나를 문자 하나로 바꾸는
  치환이므로 원문이 정확히 복원된다(FR-026).

**저장**

- **FR-027**: 저장 대상은 사용자가 확인 단계에서 확정한 항목뿐이다. 확정 이전의 중간 상태와
  사용자가 삭제한 항목은 저장되지 않는다.
- **FR-028**: 시스템은 저장 시 다음 위생 처리만 수행한다. 그 외의 내용 변형은 하지 않는다.
  - 항목 앞뒤 공백 제거
  - 내용이 없는 항목 제외
  - 줄바꿈·탭·제어문자 제거
- **FR-029**: 시스템은 각 항목을 순서와 텍스트로 저장해야 한다. 종목·강도·렙·세트로의 구조화된 값은 저장하지 않는다.
- **FR-030**: 시스템은 프로그램을 소유 사용자, 생성·수정 시각과 함께 저장하고, 다른 사용자의 프로그램이 노출되지 않게 해야 한다.
- **FR-031**: 시스템은 사용자 편집 이전의 붙여넣기 원문을 프로그램과 함께 보존해야 한다.
- **FR-032**: 시스템은 항목이 하나도 없는 프로그램의 저장을 거부해야 한다.
- **FR-033**: 시스템은 프로그램에 사용자가 식별할 수 있는 이름 또는 날짜를 부여해야 한다. 사용자가 지정하지 않으면 등록일을 기본값으로 사용한다.
- **FR-034**: 시스템은 사용자가 저장한 프로그램 목록을 최신순으로 조회할 수 있게 해야 한다.
- **FR-035**: 시스템은 사용자가 저장한 프로그램을 삭제할 수 있게 해야 한다.
- **FR-036**: 저장이 실패하면 시스템은 실패를 사용자에게 알리고, 입력한 내용을 유지한 채 재시도할 수 있게 해야 한다.

### Key Entities

- **프로그램(Program)**: 칠판 한 판에 해당하는 훈련 계획 하나. 소유 사용자, 이름 또는 날짜,
  붙여넣기 원문, 생성·수정 시각을 가지며 하나 이상의 항목을 순서대로 포함한다.
- **프로그램 항목(Program Item)**: 불릿 하나에 대응하는 최소 단위. 프로그램 내 순서와
  사용자가 확정한 텍스트만을 가진다.
- **붙여넣기 원문(Pasted Text)**: 사용자 편집 이전의 입력 원문. 사용자가 무엇을 얼마나 고쳤는지를
  측정하는 유일한 근거이며, 표기 규약을 실제 사용 데이터로 보강하는 재료다.
- **의심 구간(Suspect Span)**: 항목 텍스트 내에서 숫자 자리에 문자가 인식된 것으로 판단되는 구간.
  화면에만 존재하며 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 텍스트를 붙여넣은 뒤 60초 이내에 프로그램 저장을 끝낼 수 있다.
- **SC-002**: 「다음」을 누른 순간부터 불릿 목록이 보이기까지 사용자가 대기를 인지하지 못한다(1초 이내).
- **SC-003**: 20줄 규모의 텍스트를 붙여넣어도 SC-002의 기준이 유지된다.
- **SC-004**: 저장된 프로그램의 항목 수가 사용자가 의도한 줄 수와 일치하는 경우가 100%다
  (분해 규칙이 결정적이므로 불일치는 결함으로 간주한다).
- **SC-005**: `docs/gym-program-notation.md` 2장의 칠판 원문 6판 40줄을 입력했을 때,
  의심 구간으로 표시되는 곳이 4.1에 기록된 오인식(`2xl`, `1xl`, `3x2. 105%`, `2+1`) 외에는
  없다(오탐 0건).
- **SC-006**: 붙여넣기 원문 대비 사용자가 손댄 항목의 비율을 측정할 수 있고, 그 값이
  이후 입력 경로 개선의 판단 근거가 된다.
- **SC-007**: 프로그램 등록을 시도한 사용자의 95% 이상이 저장까지 완료한다(중도 이탈 5% 미만).
- **SC-008**: 저장 실패나 화면 이탈을 포함한 어떤 경우에도 사용자가 입력·편집한 내용이 예고 없이 소실되지 않는다.

## Assumptions

- 프로그램 등록은 로그인한 사용자만 수행하며, 기존 인증 체계를 그대로 사용한다.
- 사용자의 휴대폰 OS가 카메라 화면에서 텍스트를 인식해 복사하는 기능을 제공한다.
  이 기능의 품질은 앱이 통제하지 않으며, 그래서 US2(수정)가 P1이다.
- 칠판 원문은 `docs/gym-program-notation.md` 2~3장의 표기 규약을 따른다. 이 기능은 그 규약을
  해석하지 않고 텍스트로 보존하기만 한다.
- 프로그램 하나는 칠판 한 판, 즉 빈 줄로 구분되는 한 덩어리에 대응한다.
  한 번의 붙여넣기는 한 개의 프로그램으로 저장된다.
- 사용자당 프로그램 수는 수백 건 규모로, 대용량 조회 최적화는 범위 밖이다.
- 저장 시점에는 네트워크가 필요하다. 오프라인 등록은 범위 밖이다.
- 이 기능은 저장까지만 책임진다. 저장된 프로그램으로 훈련을 수행·기록하는 러너는 별도 기능이다.

## Dependencies

- **`docs/gym-program-notation.md` 4장 「오인식 패턴」** — FR-012의 검출 대상 단일 출처.
  2026-09-02에 신설했다. 검출 규칙을 바꾸려면 코드가 아니라 이 문서를 먼저 고친다.
- **`docs/specs/2026-07-24-program-text-paste-design.md`** — 같은 기능의 이전 확정 설계.
  2026-09-02에 본 명세로 대체하기로 결정했다. 참조하지 않는다.

## Out of Scope

- **앱 내 이미지 인식(OCR)** — 후속으로 미룬다. 도입하려면 US1이 실패 시 대안으로 남아 있어야 한다.
- **노테이션 파싱 및 구조화 저장** — 종목·강도·렙·세트 분해는 이를 소비하는 화면이 생길 때
  읽는 시점에 수행한다. 저장 스키마는 이를 위해 미리 확장하지 않는다.
- **표기 규약 적합성 검사** — FR-013 참조. 현행 문법이 실제 원문을 덮지 못하는 한 열지 않는다.
- **의심 구간 자동 수정** — 표시만 한다. 자동 치환은 틀렸을 때 사용자가 알아채지 못한다.
- **종목명 오타 검출** — 어휘 매칭이 필요하므로 제외한다.
- 프로그램 실행(러너), 세트별 수행 기록, PR 환산 계산
- 종목 어휘 자동 학습·확장
- 여러 칠판을 한 번에 일괄 등록하는 배치 처리
- 프로그램 공유, 코치 계정, 다중 사용자 협업
- 프로그램 템플릿, 반복 일정, 캘린더 연동
